# AWUN: аудит редизайна и времени отклика

Дата: 22 августа 2026 года.

## Интерфейс

Редизайн сохраняет тёмную лесную атмосферу AWUN, но разделяет экран на три
понятные зоны: постоянная навигация, поиск с очередью и сцена проигрывания.
Фон собран из оптимизированных WebP-изображений леса и замка; поверх них
используются затемнение и мягкая маска, чтобы текст оставался читаемым.

Пластинка появляется только после выбора трека. Обложка трека находится на
центральной этикетке и является частью вращающегося элемента, поэтому вращается
вместе с пластинкой. При смене трека этикетка получает короткую отдельную
анимацию без повторного выезда всего плеера.

### Контракты компоновки

| Диапазон | Компоновка | Защита от перекрытий |
| --- | --- | --- |
| `>= 1100 px` | Навигация `108 px`, очередь `480–650 px`, отдельная сцена плеера | Плеер начинается строго после первых двух колонок; консоль и пластинка имеют отдельные слои |
| `>= 1100 px`, высота `<= 820 px` | Уплотнённая боковая навигация | Уменьшены логотип, кнопки и интервалы, чтобы не обрезать Install/Theme |
| `761–1099 px` | Плеер закреплён снизу, пластинка слева от консоли | Контент получает нижний отступ `275 px` |
| `<= 760 px` | Компактная нижняя карточка, пластинка выступает сверху справа | Контент получает нижний отступ `235 px`; центр пластинки остаётся поверх карточки, заголовок резервирует место справа |
| `<= 430 px` | Только основные транспортные действия | Скрыты второстепенные feedback/repeat-кнопки; Previous/Play/Next и громкость сохранены |

Модальные панели внешнего вида и импорта находятся выше плеера по `z-index`.
Фоновая сцена не принимает события мыши. Состояния «Поиск» и «Моя музыка»
теперь взаимоисключающие и синхронизируют `aria-pressed`.

## Время отклика

### Исправлено

1. Основной поисковый запрос теперь получает полный лимит. Дополнительные
   варианты выполняются только если результатов не хватило. Раньше лимит
   делился между тремя последовательными обращениями к провайдеру.
2. Полные успешные ответы поиска кешируются на 90 секунд. Размер кеша ограничен
   256 ключами и настраивается через окружение.
3. Одновременные идентичные запросы объединяются в один запрос к провайдерам.
4. Холодное обогащение MusicBrainz имеет бюджет 200 мс; после него поиск идёт с
   локальными вариантами, а обогащение прогревает кеш в фоне. Очередь такого
   прогрева ограничена восемью задачами.
5. YouTube Data API и SoundCloud OAuth повторно используют `aiohttp`-сессии,
   включая соединения и DNS/TLS-состояние. Обновление SoundCloud-токена защищено
   от параллельного дублирования.
6. Версионированная статика получает `Cache-Control: max-age=31536000,
   immutable`, обычные изображения — кеш на сутки. Service Worker отдаёт
   закешированную статику без ожидания сети.

### Контролируемый микробенчмарк

Искусственная задержка одного провайдера: 40 мс. Это проверка алгоритма, а не
замер внешних сервисов или production-инфраструктуры.

| Сценарий | Результат |
| --- | ---: |
| Прежний план из трёх последовательных вариантов | 121,3 мс |
| Новый primary-first план | 40,3 мс, 1 обращение |
| Первый поиск с медленным обогащением | 59,9 мс |
| Повтор из кеша | 0,271 мс |
| Два одновременных одинаковых поиска | 59,0 мс, 1 обращение |

### Что измерять после развёртывания

- p50/p95 общего `/api/v1/search` и каждого источника;
- долю попаданий в кеш и число объединённых одинаковых запросов;
- частоту таймаутов и открытий circuit breaker по источникам;
- время до первого результата отдельно для API-режима и `yt-dlp` fallback.

Фактическую задержку внешних провайдеров и Render после развёртывания этот
локальный аудит не подтверждает: она зависит от ключей, региона, квот и нагрузки.
