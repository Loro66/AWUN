# SongVale 2.8.0 — завершение аудита и выпуск

Дата: 20 октября 2026 года. Основа: стабильный `main`
`4b8325945446e733638aaf8ac3c340c2a7204244` (2.7.1) и черновик PR #64
`9d0c0a77e97efdf78edfaf31f095494187dacd98`.

## Что закрыто

Сохранены все исправления 11 групп проблем [предыдущего аудита](AUDIT-2026-10-20.md):
SSRF/CSP/схемы ссылок, полное ограниченное чтение ответов, owner/recovery-метаданные,
owner-профили Волны, реакции на записи из разных источников и квалифицированное
прослушивание. Сохранены оценки, библиотеки предпочтений, непрерывная выдача,
ограничения памяти и кэширование, добавленные после начала черновика.

| Проблема | Исправление и проверка |
| --- | --- |
| Офлайн-задание и готовая копия другого владельца | Owner-профили заданий `awun-offline-profiles-v2`; старые задания перенесены к указанному owner, история без владельца — к гостю. Проверены переходы guest/account и возврат. |
| Загрузка продолжалась после смены владельца | Прерывание и поколение операции; результат старой загрузки не публикуется в новом профиле. Проверка смены owner во время сетевого ответа. |
| Очистка могла удалить общий файл другого профиля | Физические копии с одинаковым SHA-256 могут использоваться несколькими owner; удаление и вытеснение защищают чужие ссылки, импортированные и активные файлы. |
| Отложенная запись могла вернуть очищенные задания | Очистка меняет epoch профиля; старые записи отклоняются. Новые задания другой вкладки сохраняются при обычной записи. |
| Чужую копию можно было снова запустить кнопкой плеера | При смене профиля проигрывание его офлайн-копии закрывается, отменяется подготовка. Проверяются доступные файлы и прямое разрешение local audio. |
| Сохранённые альбомы были общими для разных аккаунтов | Локальные профили `awun-albums-v2`; прежняя непривязанная коллекция остаётся гостевой. Интерфейс обновляется при смене owner и восстановлении backup. |
| Ручной импорт совпадал с невидимой чужой автоматической копией | Явно выбранный пользователем файл становится обычным импортом устройства без повторного хранения аудио; браузер и Windows используют одинаковое правило. |
| Новые проигрыватель и группировка отменяли оптимизации библиотеки | Кэширование inventory, smart-подборок, нормализованного текста и выбранных записей сохранено; локальный store обновляет массивы неизменяемо для корректной инвалидации. |
| Сохранение очереди отменяло подготовленный следующий трек | Сначала запрашивается подготовленный трек, затем сохраняется изменённая очередь. Проверены отдельные media decks и реальный WAV crossfade. |
| Сохранённое семя Волны теряло рабочую ссылку в памяти | Безопасный сохранённый descriptor дополняется свежим результатом той же записи. Выключенная непрерывная выдача не запускает новый discovery; обновление истекших ссылок и разрешённых загрузок остаётся возможным. |
| Отказ записи задания оставлял вечный статус загрузки | Ошибка хранилища переводит задание в явное retryable error; таймер и running-state освобождаются. Сценарий воспроизведён отдельным тестом до исправления. |
| Предпочтение источника/crossfade терялись после Windows-перезапуска | Точные ключи настроек добавлены в JS/Python whitelist snapshot; токены сессии не сохраняются. |
| Перемотка, остановленный playhead и переходы искажали историю | Прослушивание требует продвижения playhead; source switch сохраняет сессию, repeat начинает новую, fade учитывается один раз и не переносит старое время в другой owner. |

Ручные аудиофайлы остаются коллекцией устройства. Owner-изоляция автоматических
копий и альбомных списков — логическая граница внутри приложения, а не отдельное
шифрование файлов на одном компьютере. Подписанные media permissions, проверка
типа и целостности, ограничения 100 MiB/файл и запреты скачивания YouTube/SoundCloud
сохранены. Файлы не выгружаются в публичный backend, аккаунты или portable backup.

## Поставка и проверка

Локальные Python и JS-наборы, поведенческие браузерные сценарии, реальные тестовые
WAV, owner-регрессии, версии iOS/Android и текущие store release notes проверяются
до merge. Числа и итоговые результаты CI записываются в описание PR #64.

Обязательные workflows: Windows EXE/installer/upgrade, frontend/screenshot,
dependency audit/CodeQL, Android/iOS test builds и unsigned Play AAB.
Выпуск использует корневой `VERSION=2.8.0`, соответствующие npm/iOS/Android
метаданные, действующий lock-файл и версии GitHub Actions.

## Практические ограничения

- Повторный внешний `/health` Render из среды разработки закончился таймаутом.
  Логи и фактический deployed commit без доступа к Render не подтверждены.
  Успешный merge не означает автоматически проверенный живой сайт.
- Физические iPhone/Android, Windows UAC/драйвер, звонки/Bluetooth и длительный
  фон требуют проверки на устройствах. Нативные сборки не являются публикацией
  в App Store/Google Play; их подпись и store review остаются отдельными этапами.
- Не заявляется доступность любой записи во внешнем каталоге, SLA или измеренный
  production p95. Проверки используют контролируемые ответы поставщиков.
- Прежний документ `MARKET_READINESS.md` упоминает локальные незагруженные
  доработки после 2.8. Их отсутствующий код не выдаётся за восстановленный.
- Лицензия и коммерческая модель этим техническим выпуском не меняются.
