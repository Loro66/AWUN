# AWUN: проверяемая справка о проекте

[Обзор проекта](../README.ru.md) · [English](PROJECT_CASE_STUDY.md) · [Архитектура](ARCHITECTURE.md) · [Дорожная карта](../ROADMAP.ru.md)

Эта справка описывает продукт и разработку. Это не текст вступительного эссе.
Она не содержит выдуманных отзывов, показателей аудитории или результатов пилота.

## Задача

AWUN задуман как музыкальное приложение для самого автора и его окружения:
общий поиск по нескольким источникам, сохранённая библиотека и непрерывное
прослушивание в одном интерфейсе. Одно из исходных требований владельца проекта:
Windows-приложение должно запускаться без собственного платного сервера.

## Что реализовано

- Windows-оболочка запускает встроенный Python/FastAPI API на локальном порту.
  Удалённый API используется как резерв для недоступного источника.
- Результаты поиска появляются по мере ответа отдельных провайдеров.
- Ручная очередь поддерживает добавление следующим и в конец, удаление,
  перестановку и сохранение между запусками.
- «Моя волна» использует предпочтения и наполняет очередь.
- Перед воспроизведением сохранённой записи обновляется временная ссылка.
  При сбое приложение ищет близкое совпадение у другого подключённого источника.
- YouTube воспроизводится через официальный видимый плеер. Недоступная загрузка
  временно исключается из повторных попыток восстановления.
- Waveform использует данные источника или пики прослушанных участков;
  при отсутствии таких данных используется синтетический профиль.
- Есть диагностика источников, локальные резервные копии, импорт/экспорт и журнал
  с редактированием секретов. Версия продукта определяется корневым VERSION.

## Три конкретных инженерных эпизода

### Ложная недоступность источников

Владелец проекта прислал отчёт, где API считался недоступным из-за
`Cannot set properties of null (setting 'textContent')`, хотя сервисы продолжали
работать. Это ошибка обновления интерфейса. Диагностика была разделена на
состояние API, ошибку интерфейса и сбои воспроизведения конкретного источника.

Проверяемый результат: отдельное поле `ui_error` в отчёте и независимое состояние
источников. Код: `frontend/app.js`, `backend/reliability/source_health.py`.

### Тесты проходили, но плеер ломался

Проверки наличия строк в CSS не доказывали, что браузер применяет нужный стиль.
Старые правила с `!important` имели приоритет из-за порядка CSS-слоёв. Они
возвращали скрытые кнопки и переносили громкость на дополнительную строку.

Приоритеты старых правил исправлены. Добавлены браузерные сценарии, сравнение
со скриншотами и проверки границ элементов на ширинах 1920, 1280, 1000 и 390 px.
Код: `frontend/design-system.css`, `frontend/redesign.css`,
`tests/e2e/awun.spec.js`.

### Восстановление данных само могло испортить библиотеку

Первоначальный импорт проверял оболочку JSON, но принимал несовместимую версию
и неправильные значения. Теперь версия и содержимое проверяются до изменения
хранилища. Пользователь видит количество треков и подтверждает замену.
При ошибке записи возвращаются прежние данные.

Проверяемые случаи: неправильная версия, повреждённый JSON, неверный список
треков, отмена импорта и отказ хранилища после частичной записи.
Код: `frontend/storage.js`, `tests/test_frontend_runtime.py`,
`tests/e2e/awun.spec.js`.

## Роль владельца проекта и использование ИИ

По истории работы владелец проекта формулировал требования, выбирал визуальное
направление, проверял Windows-сборки и присылал скриншоты и отчёты с ошибками.
Он требовал убрать неработающие и декоративные элементы и определял порядок
улучшений. Codex участвовал в реализации кода, поиске причин, автоматических
проверках и сборке. Описывать этот процесс как полностью самостоятельное
написание всего кода было бы неточно.

## Как проверить проект

- Репозиторий: https://github.com/Loro66/AWUN
- История работы: https://github.com/Loro66/AWUN/pull/22
- Автоматические проверки: `python -m pytest -q` и `npm run test:e2e`.
- Windows workflow: https://github.com/Loro66/AWUN/actions/runs/34261419370
- Frontend workflow: https://github.com/Loro66/AWUN/actions/runs/34261419408
- Windows-пакет содержит portable EXE, установщик и SHA-256 обоих файлов.

Браузерные тесты используют управляемые ответы источников. Они проверяют
поведение приложения при успехе и отказе, но не доказывают доступность каждого
трека в конкретной стране. Полностью офлайн-каталога и гарантии обхода всех
региональных ограничений нет.

## Какие результаты ещё предстоит получить

На этом этапе нет подтверждённых измерений аудитории, экономии времени или
пользы для сообщества. Цель «для друзей» не означает, что пилот уже состоялся.

Следующий ручной пилот: предложить трём людям найти нужную запись, составить
очередь, закрыть и снова открыть приложение, затем экспортировать библиотеку.
Для каждого задания записать результат, время и возникшую проблему. Сохранить
обратную связь с разрешения участника и исправить обнаруженные сбои.
Это план проверки, а не заявленный результат проекта.

Следующий этап описан в [дорожной карте](../ROADMAP.ru.md).
